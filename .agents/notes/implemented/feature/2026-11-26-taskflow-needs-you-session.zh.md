# Agent Note: TaskFlow 欠账写明来源聊天

Status: implemented

[English](2026-11-26-taskflow-needs-you-session.md) | 中文

## Problem

needs-you 欠账记录等人处理的事和材料所在（`ref`），但不记录是哪个聊天提出的。同一项目常有多个 Claude Code 与 Codex 聊天并行，打开详情卡的人分不清该回哪段对话找前因后果。单凭聊天 ID 看不出是哪段对话；标题存储只在一台 Mac 上，而同一看板也运行在没有这些存储的只读服务器上。

## Decision

schema-v2 `needs-you` 事件接受一个可选字段 `payload.session`，内容是来源聊天 ID，须为非空单行。[注意力账本决定](2026-08-15-taskflow-attention-bar.md)的其余部分不变：未知键仍被拒绝，该字段不参与欠账身份与收口。

宿主通过不接受路径的 `taskflow.sessionTitles({ ids })` Remote 调用把 ID 解析为显示标题。Claude 桌面会话存储、Codex 会话索引、账本旁的兜底文件 `session-titles.json` 依次作答，每个只处理尚未解析的 ID。宿主从 Claude 会话文件中只读取 `sessionId`、`cliSessionId`、`title` 与 `isArchived`，因为这些文件还保存连接器和权限设置。桌面 ID 直接读取同名文件；按文件大小和修改时间失效的逐文件记忆让 CLI ID 的重复扫描保持低成本；每个来源、文件和行都是可选的：失败只是不提供标题，调用不会因此失败。兜底文件让没有实时存储的宿主也能显示由其他进程同步来的标题。

客户端把全部未收口欠账的会话合成一次批量查询，每个已有结果缓存五分钟，并在详情卡上显示一行：「去处」与工具和标题，已归档时标（已归档）；否则在查询中或查不到标题时显示「来源会话」与短 ID。续接 prompt 带完整 ID，方便其他 AI 找到该聊天。

## Alternatives considered

**把标题写进账本事件。** 事件写入后标题仍会变化，改名会让账本过时，而只追加的账本无法更正。

**复用 `ref`。** `ref` 指向待审材料，聊天是另一项事实；混用会破坏 `ref` 为路径或分支名的现有欠账。

**每次请求不经记忆扫描全部 Claude 会话文件。** 每个文件保存整段对话，一台常用机器上全量扫描要读取 100 MB 以上。

## Consequences

写入方可以添加 `payload.session`，现有读取方中只有本校验器需要改动；写入方开始输出该字段之前，写入端及其他账本校验器必须先接受它。标题查询绝不阻塞看板：存储缺失、文件不可读或 Remote 调用失败时显示短 ID 与「标题查不到」。只读服务器只有在兜底文件同步过去后才显示标题。宿主测试用临时生成的三类来源，覆盖 Codex 重复 ID、不可读文件、超限文件与各项上限；客户端测试覆盖已解析、已归档、未解析、查询中和查询失败。
