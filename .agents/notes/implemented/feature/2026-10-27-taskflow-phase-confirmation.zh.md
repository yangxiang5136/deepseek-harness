# Agent Note: 可追溯反思的人类阶段确认

Status: implemented

[English](2026-10-27-taskflow-phase-confirmation.md) | 中文

## Problem

本人可能在对话中结束一个工作阶段，也可能点击 TaskFlow 按钮。只接受按钮确认会让已经完成的工作继续等待，接受任意来源引用又会让 AI 编造人的批准。阶段结束还需要保留材料，供以后反思。

## Decision

TaskFlow host 在原生本地对话记录的精确字节偏移处核验逐字真人消息，再复用与按钮相同的精确债务收口事务。请求中的 `surface` 为每种 AI 工具选择一个适配器；未带该字段的请求默认为 Codex，Claude Code 是第二个适配器。共用代码检查 host 固定的根目录、路径规范性、普通文件身份、行首边界、记录大小和逐字引文；各适配器确定自己的目录布局、文件命名、标记真人输入文本的记录字段，并提供各自的 `confirmation_ref` 前缀。调用者负责将本人原意映射到选中的具体债务；关键词匹配不能关闭一个项目的全部工作。其他 AI 工具只能通过依据已采集原生记录建立的专属适配器接入。

Claude Code 记录只有同时满足以下条件才算数：应用在 `origin`（恰为 `{kind: "human"}`）和 `turnOrigin` 两处都标记为本人输入；记录属于所引会话的主记录文件；来自已采样的 `claude-desktop` 入口。两处标记缺一不可：压缩摘要带真人 `turnOrigin` 但没有 origin，CI、定时任务、shell 和粘贴内容记录则带真人 origin 但文本有包装。引文必须位于应用开头提醒之后、任何注入包装之外的文本块中；含工具结果的记录一律拒绝。

详情动作直接表达本人意图：本阶段结束，交史官复盘。审计收口保留确认来源。外部史官消费者从有效精确收口派生持久且可去重的任务，另行记录实际阅读和反思。收口不证明史官已读，也不证明整个项目已获接受。原始材料与续接入口继续保留。

## Alternatives considered

- 把普通完成记录当成批准：执行与本人决定的来源不同，因此不采用。
- 允许调用者随意提供确认引用：引用需要 host 核验，因此不采用。
- 用宽泛完成关键词自动结束阶段：一句话可能只涉及仍有相关未决事项的局部阶段，因此不采用。
- 在收口时承诺反思已完成：阅读可能失败，也可能在阶段结束后仍排队，因此不采用。
- 只凭文本包装识别 Claude Code 真人消息：旁支会话的首条消息、其他会话发来的消息和压缩摘要都是无包装的纯文本，只有应用的来源标记能区分，因此不采用。
- 接受所有 Claude Code 入口：终端、IDE 和 SDK 的记录尚未采样，无头 SDK 运行携带程序生成的提示，因此不采用；采样之前一律拒绝。
- 像 Codex 拒绝分叉线程那样拒绝恢复或分叉的 Claude Code 记录：Claude Code 对续接的标记并不一致，本人输入的旁支会话同样是派生会话；真人记录的副本保留本人文字，引用指向副本，因此不采用。
- 所有工具的会话都沿用 `threadId`：各工具有自己的标识名，按变体区分字段还能让生成的线上 schema 拒绝混用的请求，因此不采用。

## Consequences

对话确认需要支持的原生记录和调用者选定的准确范围。回合运行期间输入的 Claude Code 消息是排队附件，无法引用，本人需在回合结束后再说一次。核验信任本机账户：它拒绝错配、注入和挪动过的文本，但无法拒绝能写入记录文件的进程伪造的记录。host 拒绝不支持或被注入的来源、不完整记录、缺失的逐字引文和链接路径。反思可用性由独立消费者负责，其回执必须说明实际覆盖和未决材料。界面的撤销窗口保持不变，两种入口使用同一精确收口事务。
