# @deepseek-ai/dsh-client-ui-taskflow

English | [中文](README.zh.md)

The detail action “本阶段结束，交史官复盘” ends the selected phase and preserves its source material and continuation entry. The tray checkmark uses the same audited seal after its undo window. A separate historian consumer reads sealed phases and records its actual reading and reflection; a seal alone does not claim that reflection has happened.

The bar follows [ui-theme's selected palette](../ui-theme/README.md), including grouped history colors and its banner shadow. Project identity colors remain distinct, segment labels retain dark text on the light data palette, and running, waiting, and error indicators keep their state meanings in either palette.

TaskFlow remembers its expanded or collapsed state and selected project in the versioned browser preference `dsh.taskflow.view.v1`. Refreshing, remounting, or opening a new page on the same origin restores that view; closing or clearing a project remains closed, and collapsing the bar retains the project for the next expansion. The preference changes only after local gestures, so another page does not move the current view. Debt cards and seal actions are never restored. Missing, corrupt, unsupported, or blocked storage falls back to the original collapsed view without a selected project; an unavailable write leaves the current page usable in memory.

TaskFlow bottom status bar, the first resident of the frame-wide `shell.overlay` slot: a collapsed 30px mini strip that expands into the attention surface defined by spec §6 v3.0 — a solid low-saturation time-history strip, one row of running chips, the needs-you tray, and the title popover holding no-heartbeat lanes and overflow. An empty timeline distinguishes a recorded current task from a day without ended attention periods; current work enters history after a switch or terminal event. Facts come from the bus ledger through the `taskflow` Remote namespace (`@deepseek-ai/dsh-host-taskflow`) and refold every 10 s. Timeline, current, background, and lane state remain day-scoped; `needs-you` debts fold over the complete ledger and survive day/month boundaries. A v2 debt closes only through an exact schema-v2 resolver: a `dsh` audited `done` seal or a `drop` withdrawal whose note begins `Superseded`. Legacy v1 debts retain the 60-second heuristic only for legacy terminal rows, so a future ordinary v2 terminal cannot close them. The seal checkmark sends the target `event_id` when available and `dsh-ui:seal-click` as confirmation. The bar publishes its live height as `--dsh-shell-bottom-clearance` on the shell frame so ui-layout content ends above it. Type follows one five-role scale (lead 15 / item 13 / meta 12 / ctrl 12 / hint 11px, `--tf-font-*` on the banner, mirrored by `typeScale.ts`), so size tracks importance: the current task and 待你收口 lead their surfaces. Expanded, an amber 无心跳 N badge beside the title counts silent lanes and background tasks and opens their list; a lane that went silent still closes when its orchestrator finishes, so finished work never lingers there.

The header’s 项目 selector and project names in the needs-you tray open a project’s tree (Branch Compass inside TaskFlow): the mainline with every unresolved branch forking where it began (running, stalled, waiting on you, or parked), and the project's bus todo items continuing the mainline past now. The selector includes projects with a saved review plan or activity in the last 7 days, unresolved or parked debts, saved mainline picks, or open bus todos. Todo files load on startup and when the project changes; a read failure is visible in the header or open tree. Settled branches are not drawn; they remain available in one summary line. The tree shows no branch percentage or attention-balance verdict. The mainline is the human's pick per project (a hover-revealed 设为主线 chip on each row; stored in browser `localStorage`), defaulting to the most active task. A tray row or a waiting / parked tag opens the same debt card: status, ref, note, the latest move since it was filed, the last ledger events, a copyable continuation prompt (cause, Sean's recent closing notes on the project, and the `att` commands so any AI can resume the task and keep TaskFlow in sync), and the seal with an optional one-line note — Sean's feedback, which later AIs read before working on the project. The title popover holds only no-heartbeat lanes and overflowed chips; open debts live in the tray alone. `park` debts (parked side-branches) stay out of the tray and the running rows and appear only on the tree.

Projects with a saved plan show the suggested review order immediately below the panel header and above the branch graph; projects without a plan keep the tree without an empty review section. The order comes from `taskflow.reviewPlans()`, polled every 10 seconds independently of project selection. Strict version-one plans carry ordered items, advisory predecessors, explicit ordering overrides and source-message observations. The compact list shows each native chat name from `chatTitle` verbatim, combines steps sharing a `threadId`, and keeps parallel chats in their own list. A chat with a human ordering override uses its earliest override rank; other chats use their earliest step rank. Missing native names show an explicit synchronization placeholder with the chat ID; generic items without a chat ID keep their item title. Each chat has at most one combined debt status, derived only from exact ledger identities; combining rows never closes or removes debts. A source marked pending means an observed message has not been reconciled; a saved plan timestamp does not establish synchronization. Pending sources retain their first unreviewed message reference; fresh sources carry the matching reconciled message and clear that pending reference. Source references and observer health stay in folded details. Health distinguishes unconnected, failed and stale (over 30 seconds since the last scan) local monitoring, with excluded surfaces listed separately. Invalid reads retain the last good plans and display an error. Review actions stay in the original tray, whose entries open the exact debt, including separate reviews sharing a task name; unlisted debts remain in the tray. The order list adds no copy or open-record buttons.

## Model Experience

None, as the bar is a human-facing surface over the bus ledger; nothing here reaches a model request.

#### KV Cache effect

None; this package neither assembles nor sends a provider request.

## Known Limitations and Deferred Work

- **Measured geometry mirrors CSS by hand** — text is measured at its type role (canvas `measureText`, `estTextW` fallback) against the observed row and strip widths, but the SVG tree constants in `ProjectPanel.tsx` and the chip box model in `fold.ts` `CHIP` restate CSS values; only the type tokens (`TF_TYPE`) and the chip max-widths are locked by tests.
- **Queueing actions are out of scope** (spec §6 v3.0 action table).
